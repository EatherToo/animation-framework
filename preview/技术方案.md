# preview · 技术方案（遮挡、取景与构建）

> **2026-11-21**：2D 渲染场景的架构已重定为 [ADR-000](../docs/adr/000-2D渲染架构重构.md)。本文件只保留 P1–P4 的遮挡/取景/构建实现记录；逐三角灰面、部件平均深度、3D 筒口径已被取代。

> 状态：**P1–P4 已实施**，另外补了取纹理的重试与单文件打包。本文只管 `preview/` 这个演示页，不改 `packages/render-engine/`。
> 页面现状与跑法见 [README.md](./README.md)；人体比例的目标与验收见 [../docs/人体写实化技术方案.md](../docs/人体写实化技术方案.md)。

## 0. 目标与边界

### 0.1 要改什么

1. **遮挡**：后景肢体的描边不再压到前景部件上。
2. **深度粒度**：从「整件平均深度」走到「逐像素深度」，肢体交叉时前后关系正确。
3. **取景**：跟随当前姿态，而不是永远按绑定姿态的包围盒。
4. **构建**：把「构建引擎 → 生成纹理 → 打包页面」收成可重跑的命令，并在纹理与网格对不上时给出明确报错。

### 0.2 不改什么

| 保留 | 说明 |
|---|---|
| 引擎 | 不改 `packages/render-engine/` 的任何模块与导出 |
| 画法 | 灰度三角面 + 黑色描边 + 正交正面，不做光照与透视 |
| 交互 | 右侧关节滑块、复位按钮、活动范围显示 |
| 数据 | 每个三角形一张 16×16 灰图，不走外部贴图 |

### 0.3 判据

任何姿态下，被挡住的部分不出现可见的边线或色块；取景不出画、不裁切；一条命令能重建页面。

## 1. 现状（代码事实）

`draw()`（`main.ts` L229–L268）一次画面做四件事：

```text
取景框固定：const restFrame = contain(...) 在模块加载时按绑定姿态算一次（L75），
            每帧只用 fit(restFrame) 缩放（L251）
投影        projectParts(sampled, FRONT_VIEW)
三角化      fillProjected / textureProjected / strokeContours
排序        depthOrder(...) 按整件平均深度（引擎 view/project.ts L175–L199）
绘制        先 paintTextures 把所有部件的面画完（L257），
            再遍历 order 画所有部件的描边（L261–L267）
```

由此得到三个可复现的问题：

| 问题 | 原因 | 后果 |
|---|---|---|
| 后景描边穿透 | 所有描边都在所有填充之后画 | 被躯干挡住的腿仍能看到黑边，形体像断裂 |
| 整件深度不够细 | `depthOrder` 只比较部件平均深度 | 两条腿交叠时整条腿的先后颠倒 |
| 部件内部无深度测试 | `paintTextures` 逐三角形直接覆盖像素（L270–L325） | 同一部件内远近三角形互相覆盖，自遮挡错 |
| 取景不跟随 | `restFrame` 固定 | 姿态展开时裁切，收起时留白过多 |

另有两个工程事实：

- 纹理：`generate-textures.mjs` 为每个三角形写一张 16×16 灰图，当前 7968 张；`loadGrayTextures` 用 `manifest.json` 的 `count` 校验网格，对不上就抛错、整页不渲染。
- 构建：`index.html` 只加载手工打包的 `main.js`；仓库里没有构建脚本。已验证可逐字节复现当前产物：

```bash
./node_modules/.bin/esbuild preview/main.ts \
  --bundle --format=iife --tsconfig=tsconfig.json \
  --outfile=preview/main.js
```

引擎侧 P1–P5 没有改变三角形张数（仍为 7968），所以现有纹理目录仍然有效。

## 2. 方案：单深度缓冲，填充与描边共用

### 2.1 为什么不是「按部件先填后描」

把绘制顺序改成「一件填完接着描这一件」能解决跨部件的描边穿透，但解决不了两件事：

- 同一部件内部三角形没有深度测试，弯曲时仍会自遮挡错；
- 两个部件互相穿插（例如小臂横过胸）时，整件排序本身就不成立。

所以最终要落到逐像素深度。

### 2.2 数据结构

```ts
type DepthBuffer = {
  readonly width: number
  readonly height: number
  /** 每像素最近深度，越大越远；初值 +Infinity */
  readonly depth: Float32Array
}
```

深度沿用引擎的投影约定（`view/project.ts:99`）：

```text
screenX = x·cos + z·sin
screenY = y
depth   = z·cos − x·sin      // 越大越远
```

`preview` 自己按 `viewAngle(FRONT_VIEW)` 算顶点深度，不改引擎接口。

### 2.3 光栅化

对每个三角形：

1. 三个顶点先乘 `frame` 得到屏幕坐标，深度按上式算出。
2. 用现有的重心坐标循环遍历包围盒（`paintTextures` 里的那套），插值出每像素深度。
3. 深度小于缓冲值才写颜色并更新缓冲；相等时按部件 `order` 决定（同一深度的共面情形）。

描边也在同一张缓冲上画：把每条 stroke quad 拆成两个三角形，深度取边两端深度的较小值再减一个偏置 `1e-4`（向相机方向），保证描边压在所属部件表面之上，但压不过更近的部件。

背景先填 `#5c5c5c`，深度写 `+Infinity`。

### 2.4 背面剔除

正交投影下模型是闭合的，屏幕顺时针的三角形一定背对相机。`windIndices` 已把它们整理成逆时针，绘制时可以整片跳过，减少一半 overdraw。前提是：只对闭合部件剔除，开口部件（手、脚、头、躯干的开口环）仍按现有绕向画。

### 2.5 复杂度的退路

如果 CPU 光栅化加深度后掉帧，退一步做**全局逐三角形画家排序**：把所有部件的三角形按质心深度降序排成一张表，填充按这张表画；描边按所属部件的平均深度插进同一张表。这能修掉大部分穿透，但相交几何仍可能错，属于过渡方案。

## 3. 取景

现状 `restFrame` 在加载时算一次。改为每帧按当前姿态的投影包围盒 `contain()`，再 `fit()`。

需要保留一条约束：**最小缩放**。否则姿态收拢时角色会被放大到撑满画面，与展开时不可比。建议：

```text
bounds = contain(当前姿态投影)
scale  = min(fit.scale, fit(baseline).scale)
```

即：最多放大到绑定姿态的取景比例，不再更大；展开时按实际包围盒缩小。

## 4. 构建与纹理

### 4.1 构建脚本

新增 `preview/build.mjs`，并给 `preview/package.json` 加脚本：

| 脚本 | 内容 |
|---|---|
| `build:engine` | `pnpm -C .. build` |
| `textures` | `node generate-textures.mjs` |
| `bundle` | 上文的 esbuild 命令 |
| `build` | 依次跑 `build:engine` → `textures` → `bundle` |

### 4.2 纹理的取数方式（实施时调整）

原设计是「检查 `dist` 是否比源码新」。实施时发现：`dist` 的入口是给打包器用的，`dist/index.js` 用无扩展名的目录导入，Node 直接 `import` 会抛 `ERR_UNSUPPORTED_DIR_IMPORT`，所以这条路径本来就走不通。

改为：`build-textures.mjs` 用 esbuild 从源码打包 `generate-textures.mjs` 再执行。纹理永远按当前源码生成，不需要新鲜度检查。

页面端仍然保留校验：`loadGrayTextures` 失败时，把「部件名、清单张数、网格三角形数、建议命令」写进页面上的错误条。

实测补充：网格涨到 17144 个三角形后，按「每三角形一个 PNG」加载会在并发下被静态服务器重置连接（2010 个请求挂 23 个），页面直接报 `Failed to fetch`。因此改成：

1. 生成端写一个 `packed.bin`（每三角形一个灰度字节），页面一次请求取回；
2. 取资源带 4 次重试与退避，单次抖动不再让整页失败。

### 4.3 纹理与网格的耦合

三角形的张数由引擎的站点数与分段决定。引擎侧任何改拓扑的改动都要重跑 `textures`；`build` 脚本把这一步固定下来。

## 6. 验收

1. **遮挡**：把一侧手臂摆到躯干前，手臂的描边完整、躯干的描边不穿过手臂；反向再测一次。
2. **深度**：两条腿前后交错 30°，近腿完整遮住远腿，接缝处不出现远腿的黑边。
3. **内遮挡**：肘弯 120°，前臂自身不出现背面三角。
4. **取景**：手臂平举时画面不裁切；回收后角色不被放大超过绑定姿态的比例。
5. **构建**：删掉 `main.js` 与 `textures/` 后，`pnpm build` 能重建并可打开。
6. **纹理过期**：故意改一个站点数不重建 dist，`textures` 必须报错而不是静默生成。

## 7. 风险

| 风险 | 表现 | 处理 |
|---|---|---|
| CPU 光栅化变慢 | 大画布下掉帧 | 先加背面剔除；仍慢则退到逐三角形画家排序（§2.5） |
| 描边偏置不当 | 描边被自身表面盖住，或浮在别的部件上 | 偏置取 `1e-4` 量级，按像素深度线性缩放；用验收 1、2 校准 |
| 深度相等 | 共面三角形闪烁 | 相等时按部件 `order` 与三角形索引决定，保持稳定 |
| 取景变化 | 与旧截图不可比 | 在 README 里写明取景规则；对照图统一用同一姿态 |
| 纹理契约 | 引擎改拓扑后页面白屏 | 由 `build` 脚本与 §4.2 的提示兜住 |
